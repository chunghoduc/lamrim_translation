## Decisions already locked in

_Do not relitigate these mid-project without recording why._

- Target language: Vietnamese. Deliverable: Markdown, translation-only (no bilingual layout).
- Repair happens at CID level via our own content-stream interpreter, NOT by regex over decoded text.
- source/raw/glyphs/ is the permanent audit trail and is never edited. Everything downstream is a reproducible transform.
- Every repair-table entry requires TWO independent signals that agree. Score alone is not sufficient - see FINDINGS.md 8.5.
- CIDs with no decisive evidence are left UNREPAIRED rather than guessed; each keeps a value that decodes to a valid Tibetan syllable.
- Reference (do not copy) the existing Vietnamese Bo De Dao Thu De Quang Luan and the Snow Lion English translation for terminology checking only.
- The outline is built from the book's OWN contents (dkar chag, pp. 8-20) cross-checked against the printed sa-bcad headings - two independent sources that must agree. 284/284 agree exactly. Do not rebuild it from heading detection alone.
- Nesting depth comes from the RANK of the contents' indent column, not from rounding onto a fitted grid: the columns drift ~0.9pt, so a grid fit would be a judgement call dressed up as arithmetic.
- Three places where the printed indentation skips a level are the SOURCE's own structure and are kept as printed, not normalised (recorded in source/outline.json notes).
- Chunks start on section boundaries. Leaf sections longer than 5 pages are split into labelled parts (part: '2/8', startsAtHeading: false) so an artificial break is never mistaken for a section break.
- SCOPE: translate everything. All 978 pages are chunked except the 13 contents pages (pdf 8-20), which are regenerated from the translated section titles at assembly rather than translated as prose - otherwise the index would drift from the headings it indexes.
- pdf 21-23 is ROOT TEXT (Namo Guru Manjughosaya + the homage verses), not front matter. It carries no sa-bcad heading, so any chunking that starts at the first heading silently drops it. Chunk c004.

## Continuing on another machine

Everything needed to carry on translating is in the repo. The 116 MB glyph trail and the
PDF are only needed to *re-extract*, not to translate.

```
git clone <repo> && cd lamrim_translation && npm install
node tools/32-chunk.mjs doctor      # reconcile progress.json against translation/
node tools/32-chunk.mjs batch 25    # -> args for the lamrim-translate workflow
```

Run `doctor` first. Each chunk records the hash of the Tibetan it was made from and the
hash of the file it produced, so a half-finished batch, a hand-edited file, or a
translation whose source moved under it are all detected rather than assumed away.

## Rebuilding from scratch

If `source/clean/` is ever lost or a repair table changes:

```
node tools/11-extract-glyphs.mjs   # PDF -> source/raw/glyphs  (only if raw/ is gone)
node tools/16-build-text.mjs       # raw + repair tables -> source/clean
node tools/30-progress.mjs --verify
```
